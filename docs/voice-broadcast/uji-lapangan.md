# Protokol Uji Lapangan — Suara Rombongan (Masjidil Haram)

Tujuan: mengukur **keandalan nyata** fitur siaran suara di berbagai kondisi Masjidil Haram,
sebelum memutuskan sejauh mana bisa diandalkan (vs handy talky / HT).

Diisi oleh **petugas/muthawwif** di lapangan. Tidak perlu alat teknis — cukup amati & catat.

---

## 1. Persiapan (sebelum ke Haram)
- **3 HP** sudah pasang aplikasi versi terbaru, sudah login akun **satu rombongan yang sama**
  (1 muthawwif = penyiar, 2 jamaah = pendengar). Uji sekali di hotel: suara harus keluar.
- Tiap HP: **earphone**, **power bank**, kecerahan layar cukup.
- **SIM data lokal** aktif di HP muthawwif (penyiar = titik paling kritis).
- Catat jenis jaringan tiap HP saat uji: **4G / 5G / WiFi** + jumlah bar sinyal.
- **Sambungkan saluran sebelum masuk keramaian** (di pelataran/bus), biarkan tetap terbuka.

## 2. Skenario yang diuji
Uji di kombinasi **lokasi × waktu** berikut (semampunya; makin banyak makin baik):

| Lokasi | Waktu ramai | Waktu sepi |
|---|---|---|
| Pelataran/halaman luar | ☐ | ☐ |
| Mataf (area tawaf) | ☐ | ☐ |
| Koridor Sa'i | ☐ | ☐ |
| Lantai atas / atap | ☐ | ☐ |

*Ramai = sekitar Maghrib–Isya, Jumat, atau saat padat. Sepi = larut malam / pagi.*

## 3. Prosedur tiap uji (5 menit)
1. Semua HP buka **Suara Rombongan**, pastikan tertulis **"Terhubung"** + jumlah orang benar (3).
2. Muthawwif tekan **Mulai Siaran**, lalu **baca doa/hitung "satu…dua…tiga…" pelan & terus-menerus** selama 5 menit.
3. Dua jamaah **dengarkan lewat earphone** dan catat di lembar bawah.
4. Catat juga berapa kali muncul status **"Menghubungkan"** di layar (di penyiar & pendengar).

## 4. Lembar catatan (salin per uji)
```
Tanggal/Jam         : __________   Lokasi: __________   Kondisi: ramai / sepi
Jaringan penyiar    : 4G / 5G / WiFi   —  sinyal: __ bar
Jaringan pendengar  : 4G / 5G / WiFi   —  sinyal: __ bar

Kualitas suara (lingkari): 1 (tak terdengar)  2  3 (putus-putus)  4  5 (jernih)
Jumlah suara terputus dalam 5 menit : ____ kali
Rata-rata lama tiap putus            : ____ detik
Berapa kali status "Menghubungkan"   : ____ kali
Jeda/telat suara terasa?             : tidak / sedikit / banyak
Catatan lain                         : ____________________________
```

## 5. Kriteria keputusan (kasar)
| Hasil di suatu kondisi | Kesimpulan |
|---|---|
| Suara 4–5, putus <2×/5mnt | **Andal** — bisa jadi utama di kondisi itu |
| Suara 3, putus 2–5×/5mnt | **Pelengkap** — pakai, tapi HT tetap siaga |
| Suara 1–2, sering putus | **Belum andal** — pakai HT di kondisi itu |

## 6. Catatan penting
- **Jangan mengandalkan fitur ini untuk komunikasi darurat.** Untuk darurat, tetap gunakan
  HT dan/atau tombol **SOS** di aplikasi.
- Wajar bila di puncak keramaian sering "Menghubungkan" — jaringan seluler memang jenuh di
  sana. Fitur ini menyambung ulang otomatis, tapi ada jeda.
- Kirim hasil lembar catatan (foto/ketik) + **jam uji** ke admin → log server bisa dicek untuk
  angka objektif (jumlah reconnect, kehilangan paket, jitter) per sesi.
